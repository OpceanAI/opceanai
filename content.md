## 0. Core idea

OpceanAI.com should not feel like a normal company website.  
It should feel like the official presentation layer of a living research organization: precise, elegant, calm, deeply technical, and emotionally coherent.

The site must communicate three things at once:

1. **OpceanAI is a technology organization**
2. **OpceanAI is an ecosystem, not a single project**
3. **OpceanAI has a real story, real evolution, and a clear future**

The tone should feel like a product launch at an Apple event:

- very polished
- very confident
- highly structured
- minimal visual noise
- emotionally controlled
- extremely deliberate typography and spacing
- each section introduced as a “moment”

The content should be displayed in parts, with rhythm and pause between sections.  
Each block of information must feel like a chapter reveal.

# 16. Section: Future vision — ASL

## 16.1 Section title

**ASL — Android Subsystem for Linux**

## 16.2 Narrative

The next step for OpceanAI is **ASL**, an alternative to Microsoft’s WSL.

ASL is focused on implementing a complete Linux kernel running in userspace, so that Linux applications believe they are running on native Linux rather than Android.

To the Android system, ASL appears as just another process consuming resources.  
But internally, it is a real kernel.

## 16.3 Technical direction

ASL is envisioned as:

- built in **C++**
- built in **Rust**
- using a modified **proot** layer for syscall handling
- kernel-first, not distribution-first

OpceanAI will not build a distribution.  
Only the kernel.

The rest is intended for the community.

## 16.4 Development condition

ASL development begins once **Doki v1** is complete.

## 16.5 Presentation note

This section should be framed as a future chapter, not as an already-finished product.

Use language like:
- planned
- envisioned
- next phase
- future layer

## 17.4 Research: NHE — Not Humanity Exam

### What is NHE?

Every existing benchmark — HLE, MMLU, BIG-Bench, ARC — measures nearly the same dimension:

What a model knows.  
How much human knowledge it can reproduce.  
How accurately it can reason.

NHE asks a fundamentally different question:

Not how much the model knows.

But how human it still thinks.

NHE measures the presence of six cognitive patterns structurally embedded within human language itself.

These are patterns that systems trained on human text cannot fully escape regardless of scale, capability, or intelligence level.

NHE serves as an empirical implementation of The Imprint Theory.

Rather than measuring accumulated knowledge, NHE attempts to measure traces of human cognitive structure remaining inside artificial systems.

# 19. Apple-event presentation style guide for the page

## 19.1 General tone

The page should sound like a keynote announcement, not a blog post.

Avoid:
- messy paragraphs
- too much technical clutter on the first screen
- random personality shifts
- chaotic visual transitions

Prefer:
- short statements
- controlled reveals
- crisp pacing
- clear hierarchy
- confident messaging

## 19.2 Section rhythm

Each section should follow this pattern:

1. Small section label
2. Large headline
3. One sharp sentence
4. One supporting paragraph
5. A highlight or metric
6. Optional visual accent

## 19.3 Spacing

Use very generous spacing.

The page should breathe.

Every chapter should feel like its own scene.

## 19.4 Motion

Motion should be subtle:
- slow fades
- gentle parallax
- glass reflection shifts
- soft transitions
- calm expansion/reveal effects

No aggressive motion.

No noisy transitions.

## 19.5 Visual hierarchy

The order of importance should always be obvious:

1. name
2. headline
3. chapter title
4. body text
5. technical details
6. external links
